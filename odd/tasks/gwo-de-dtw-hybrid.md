# GWO–DE hybrid with DTW/DDTW fresh-window control (binary MKP)

Branch `feat/gwo-de-dtw-hybrid` from `main` @ 2458683. Implements the contract proposed in chat on top of `planes/GWO_DE_DTW_DDTW.md`.
Code lives in the self-contained top-level folder `gwo_de_dtw/` (`problem.py` ported from `hybrid_mkp/mkp_core`, monitor imported from the root `dtw_stagnation.py`, not copied; neither source is modified). Instances from `instancias/`. Tests: `tests/test_gwo_de_dtw.py` (unittest).

## Specs

- S1 Shared population: each individual keeps `x_real` (init `U[-100,100]`), `x_bin` and `fit`. One repair function for everything: `gwo_de_dtw/problem.py::reparar`, with `hybrid_mkp/mkp_core/repair.py` semantics: density `min_i(p_j / r_ij)` with infinite values replaced by 10 x the maximum finite value (as `hybrid_mkp/mkp_core/problem.py`); expulsion from lowest to highest density until feasible; insertion from highest to lowest density, skipping items that do not fit. Instances are parsed as in `hybrid_mkp/mkp_core/data_loader.py`; the known optimum is the header value, or the sibling `instancias/mkcbres.txt` best-feasible table for any supported instance index (S13). Binarization is LB2 (S11).
- S2 Operators compete per individual: each generation every individual produces one GWO candidate (three leaders, parameter `a`) and one `DE/rand/1/bin` candidate (`F`, `CR`); the better of the two replaces the individual when `fit_candidate >= fit[i]`, writing `x_real` and `x_bin` together. Real vectors are clipped to `[-100, 100]`. The operators live in `gwo_de_dtw/gwo.py` (GWO) and `gwo_de_dtw/de.py` (DE); `hybrid.py` only combines them.
- S3 Leaders alpha, beta, delta are copied at the start of each generation (no row aliasing).
- S4 Profiles change GWO and DE together: exploit `a=0.5, F=0.5, CR=0.9`; explore `a=2.0, F=0.9, CR=0.3`. For LB2 the profiles also carry `G3`: exploit `0.1`, explore `0.1` (`G1` and `G2` stay fixed at `0.5`). Search starts in exploit.
- S5 Stop after `ITERATIONS` generations (S12). Evaluations = repaired candidates: "Se cuentan las candidatas reparadas. Con este esquema son 2N por generación." With LB2 (S11) each candidate costs 2, so a generation costs 4N; initialization costs N. Evaluations are counted and reported (result and CLI) but there is no evaluation budget and they never stop the run. Global best only improves with strict `>`.
- S6 Signal: best-so-far fitness per generation, window = last W observations (never unbounded), DTW or DDTW via `StagnationConfig.use_ddtw` (DDTW by default). The monitor is imported from the root `dtw_stagnation.py` (the module `hybrid_mkp` uses); no copy.
- S7 Fresh window: after each profile change the monitor is reset (window, `no_improve_len`, `trigger_streak`, threshold histories); no decision until W new observations. Global best and population are not reset. The change affects the next generation.
- S8 Decision rule: in exploit, `fire` -> explore. In explore, return to exploit when `no_improve_len < plateau_max` on a ready observation; otherwise stay. ("Si la curva vuelve a mejorar, se regresa a explotar. Si sigue estancada, se mantiene la exploración.")
- S11 "cambia a lb2": binarization is LB2 ported from `lb2/binarization.py` into `gwo_de_dtw/binarization.py`: `L1 = clip(-G1*v/(v_max-G2)+G3,0,1)`, `L2 = clip(G1*v/(v_max-G2)+G3,0,1)`; flip the individual's current bits with L1 and L2, repair both, keep the better (L2 on ties). Defaults G1=G2=0.5, v_max=100; G3 is the active profile's base flip probability (exploit 0.1, explore 0.1, config EXPLOIT_G3 / EXPLORE_G3); the same value in both profiles is a fixed G3 (both 0.1 reproduces the earlier fixed G3=0.1 run). The hybrid passes that profile G3 (constructor has G1 and G2 only). G2 >= v_max rejected (library ValueError, CLI exit 2). Initial bits = positive real coordinates, repaired. Flips use the seeded generator.
- S13 "deja lops optimos dentro de las mismas intancias osea en la misma carpeta y si  deja de depender de DTW_optimization-main. no quiero depenmde de esp es referencia": best known values for all 270 instances come from `instancias/mkcbres.txt` (unmodified OR-Library file, first table), looked up next to the instance file by `m.n-idx` name; missing file or entry -> optimum 0 (gap n/a). No reference to DTW_optimization-main in gwo_de_dtw or its tests.
- S14 "ejecutalo con sigmoide"; clarified "Opción para elegir" and "[-6, 6] con sigmoide": binarization is selectable, `config.BINARIZATION = "lb2"` (default) and CLI `--binarization {lb2,sigmoid}`; any other value is rejected (library ValueError, CLI exit 2). Sigmoid (`gwo_de_dtw/binarization.py::sigmoid_binarize`): `P(bit=1) = 1/(1+exp(-v))`, bits sampled with the seeded generator, then `problem.reparar`; one evaluation per candidate, so a generation costs 2N; initial bits sampled from `x_real`, repaired (1 evaluation each). With sigmoid the continuous space is `[-6, 6]` (`config.SIGMOID_V_MAX = 6.0`, init and every clip) and the `G2 < v_max` check does not apply. LB2 is unchanged: `[-100, 100]` (`V_MAX`), 2 evaluations per candidate, 4N per generation. Result `binarization` is the value used (`G` is `{"G1", "G2", "G3_exploit", "G3_explore"}`, only meaningful for lb2; sigmoid records profile G3 but does not use it). CLI first line `instance=<file>[<idx>] binarization=<b> signal=<sig> W=<W> pop=<N> iterations=<T> seed=<s>`.
